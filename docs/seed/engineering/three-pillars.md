# Three pillars

The structural side of SPLectrum's engineering language game. SPLectrum engineering approaches the seed from the POV of data — data is primary; everything else is embedded in the data fabric as metadata.

**Mycelium — the data fabric.** The ground. Data is the substance here: what being and the other are made of in this view. Mycelium distributes data across owners' views, reflecting both shared data state (what converges across owners) and the owner's internal subject reality (experienced-only, not shared).

**SPLectrum — the language fabric.** Metadata on the data fabric. Where protocols (language game units) are composed into personas (language game roles). In this architecture, protocols are *data transformations* — the relational of P1 expressed as transformations of data state, not as function calls.

**HAICC — the cognition fabric.** Metadata on the data fabric. Distributed cognition — who contributes which transformations, with what intent. Carries the AI integration as peer-level participation in the work.

Open architecture: interaction is data transformation, not encapsulated functionality bodies consuming and spitting data as payload. This flips the default microservice view — where microservices make functionality primary and data secondary, SPLectrum makes data primary and functionality appears as transformation of data state.

Decentralisation runs through two aspects: data state (Mycelium distributes across owners) and cognition (HAICC as peer collaboration). The language fabric is where they cohere.
