The identifier does not point to five different things. It is one thing with five dimensions — each realised when read through the right schema. `spl.mycelium.xpath.data.uri.get` is a namespace path, a protocol operation, a schema definition, a routing address, and a concept vocabulary entry. Not five identifiers. One identifier, readable as each of these through a different lens. The same pattern as everywhere in SPLectrum — multiple readings of the same reality.

The grammar has two primitives. Dot separates namespace segments — tree navigation, positional namespace, the path is the qualification. Underscore opens property bags — lateral, schema-assigned namespace. AVRO identifiers are underscore-free. They live purely in the namespace dimension. The property bags they point to are where the metadata lives, but the identifier itself is a dot-separated path through the tree.

The backbone is emerging. `spl.*` as framework top-level. Under it: mycelium with its fabric, layers, xpath, protocols. Under mycelium: avro, git, kafka as the committed languages. This is real structure — not a design document but a tree that grows from the leaves. Not rigid either. Other top-level nodes can exist. The namespace is open by default. What nobody composes doesn't exist. What someone composes, exists if it resolves.

Use an identifier sufficient for the context, no more. Within a reference library page already scoped to mycelium, `xpath.data.uri.get` is enough. In a blog post addressing a broader audience, `mycelium.xpath.data` shows the mycelium context. In a cross-system integration, `spl.mycelium.xpath.data.uri.get` carries the full qualification. Mapping between these scopes is decentralised, multi-pass, operating at all levels. The execution context carries the mapping state. All referencing beyond local scope is hidden — you see the identifier at the resolution level that matters to you.

The identifier is the carrier, not the meaning. It is opaque until read through a schema. Don't impose interpretation at the carrier level. The reader determines what each dimension means. The same identifier read through a protocol schema is an operation. Read through a concept schema it is a data structure definition. Read through a routing schema it is a dispatch address. The carrier stays the same. The reading changes.

Version is metadata, not name. Advisory to resolution, not a gate. When something diverges beyond what can be read as the same thing — when a reader schema can no longer conform — it is not a version increment. It is a new namespace node. A new concept. The old one still exists. Both are available. Resolution determines which one fits. Versioning as discovery, not as a numbering scheme.

And metadata is always ambiguity. Always contextual, always potentially different at every node on the ancestor axis. Same identifier, same version set, different metadata at this node versus that one — different resolution behaviour. The namespace does not prescribe meaning. It provides the structure within which meaning is locally determined. The subject shapes its own view of the namespace the same way it shapes its own reliability landscape through mutability declarations.
