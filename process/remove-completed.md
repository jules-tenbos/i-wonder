# Remove completed items from planning files

When a step in a planning or tracking document is complete, delete it from the file — both its detail section and any execution-order entry. Don't strike through, don't leave a "done" marker, don't archive in-place. When a whole planning file has served its purpose, delete the file itself — don't let it linger as a stale artefact.

## Why

Planning files are forward-looking. Keeping completed items around clutters the live view of what's left, invites re-reading material that's no longer actionable, and makes the file grow without signal. Old content goes out of context and starts to read as false reality — it gets consulted as if live and sends work in the wrong direction. Git history preserves what was done — the file itself should show only what remains.

## How to apply

After marking anything done, remove it from the planning file in the same edit. When the planning file's track is closed, promote any still-useful framing into its durable home (tone-of-voice, process, README, ref lib) and delete the file. This applies to `scheduled-tasks.md` and any future tracking doc.

**Exception:** if a completed step produces durable context needed for next steps (e.g. a decision record), move that context into the relevant remaining section rather than leaving the "done" entry as its host.
